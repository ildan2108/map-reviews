# Map Reviews

Тестовое задание: подключение карточки организации на Яндекс.Картах, сбор отзывов и отображение рейтинга.

## Стек

- **Backend:** Laravel 13, PHP 8.5
- **Frontend:** Vue 3, Composition API, Vue Router
- **API-аутентификация:** Laravel Sanctum
- **База данных:** PostgreSQL 16
- **Очереди:** Laravel Queue
- **Сбор данных:** HTTP-запросы к страницам Яндекс.Карт + разбор встроенного JSON-состояния страницы
- **Контейнеризация:** Docker Compose
- **Сборка frontend:** Vite

---

## Функциональность

Приложение состоит из двух основных экранов:

### Авторизация

Регистрация не предусмотрена. Для демонстрации используется один seed-пользователь.

После авторизации пользователь получает доступ к настройкам организации.

### Настройки организации

Пользователь может указать ссылку на карточку организации в Яндекс.Картах.

Поддерживаются как прямые ссылки на карточку организации, так и ссылки на карту/POI. Перед парсингом ссылка приводится к каноническому URL организации.

После сохранения запускается фоновая задача, которая получает данные организации и отзывы.

В интерфейсе отображается состояние парсинга:

- `pending` — задача поставлена в очередь;
- `processing` — данные загружаются;
- `completed` — данные успешно загружены;
- `failed` — произошла ошибка.

Frontend периодически запрашивает актуальное состояние организации без перезагрузки страницы.

### Данные организации

После успешного парсинга отображаются:

- название организации;
- средний рейтинг;
- количество оценок;
- количество отзывов;
- список отзывов.

Для каждого отзыва отображаются:

- автор;
- дата;
- текст;
- оценка.

Отзывы загружаются по 50 записей на страницу.

## Архитектура

Основная последовательность обработки выглядит следующим образом:

```text
Vue 3 SPA
   │
   │ HTTP
   ▼
Laravel API
   │
   ├── OrganizationController
   │
   └── ReviewController
          │
          ▼
     PostgreSQL

После сохранения ссылки:

Vue
 │
 ▼
PUT /api/organization
 │
 ▼
OrganizationController
 │
 ▼
ParseOrganization Job
 │
 ▼
Laravel Queue
 │
 ├── YandexMapsUrlResolver
 │
 └── YandexMapsParser
       │
       ▼
   Яндекс.Карты
       │
       ▼
   PostgreSQL
```

Контроллеры отвечают только за HTTP/API-уровень.

Логика работы с Яндекс.Картами вынесена в отдельные классы:

- `YandexMapsUrlResolver` — проверяет и разрешает URL организации;
- `YandexMapsParser` — получает и разбирает данные Яндекс.Карт;
- `ParseOrganization` — фоновая задача, координирующая процесс получения и сохранения данных.

Это позволяет не смешивать HTTP-логику приложения с логикой парсинга внешнего источника.

# Подход к парсингу

У Яндекс.Карт нет подходящего официального API для получения необходимых данных организации и отзывов, поэтому используется парсинг страниц Яндекс.Карт.

Вместо headless-браузера выбран разбор HTML-ответа и встроенного JSON-состояния страницы (`state-view`).

Из состояния страницы извлекаются данные организации и коллекция отзывов, после чего данные приводятся к внутреннему формату приложения.

### Почему выбран этот подход

**Преимущества:**

- не требуется запуск Chromium/другого браузера;
- меньше потребление памяти;
- быстрее выполняются запросы;
- проще запускать в Docker;
- проще масштабировать обработку через очередь;
- не требуется имитировать прокрутку страницы;
- данные отзывов доступны в структурированном виде внутри ответа страницы.

**Недостатки и риски:**

- `state-view` является внутренней структурой Яндекс.Карт, а не публичным API;
- Яндекс может изменить формат данных;
- при изменении структуры необходимо обновлять парсер;
- возможны ограничения и защита от автоматизированных запросов со стороны Яндекса.

# Устойчивость к изменению разметки

Парсер не рассматривает отсутствие данных как успешный результат.

При обработке проверяется наличие ожидаемого состояния страницы и структуры данных организации/отзывов.

Если:

- страница вернула пустой ответ;
- `state-view` отсутствует;
- JSON состояния невозможно распознать;
- данные организации не найдены;
- коллекция отзывов отсутствует на первой странице;

генерируется специальная ошибка источника.

В этом случае фоновая задача переводит организацию в статус `failed`, а ошибка записывается в лог и отображается пользователю.

Таким образом, изменение структуры Яндекс.Карт не должно незаметно приводить к сохранению пустых данных как к успешному парсингу.

Для страниц после первой отсутствие следующей коллекции отзывов рассматривается как окончание доступной пагинации.

# Пагинация отзывов

Яндекс.Карты возвращают отзывы порциями.

Парсер последовательно запрашивает страницы:

```text
page=1
page=2
page=3
...
```

Каждая страница содержит до 50 отзывов.

Парсинг продолжается до тех пор, пока очередная страница возвращает отзывы.

Если следующая страница не содержит коллекцию отзывов, она считается концом доступной пагинации.

Полученные отзывы сохраняются в PostgreSQL, после чего frontend получает их через API по 50 записей на страницу.

Таким образом, при переключении страниц frontend не обращается повторно к Яндекс.Картам.

---

# Фоновая обработка

Парсинг организации и отзывов выполняется через Laravel Queue.

После сохранения ссылки HTTP-запрос не ожидает завершения полного парсинга.

Вместо этого создаётся `ParseOrganization` Job.

У Job предусмотрены повторные попытки:

- до 3 попыток выполнения;
- задержки между повторными попытками — 10 и 30 секунд.

Это позволяет избежать выполнения длительного парсинга внутри HTTP-запроса и создаёт основу для масштабирования обработки нескольких организаций.

Например, при наличии большого количества организаций задачи могут обрабатываться несколькими queue workers.

Frontend отслеживает состояние задачи через API и показывает пользователю текущий статус.

---

# Обработка ошибок

Для ошибок, связанных с источником данных, используется отдельное исключение `YandexMapsSourceException`.

Обрабатываются, в частности:

- некорректная ссылка;
- ссылка не ведёт на Яндекс.Карты;
- недоступность Яндекс.Карт;
- пустой ответ;
- невозможность определить организацию;
- изменение ожидаемой структуры ответа;
- отсутствие отзывов в ожидаемой структуре.

Ошибки источника преобразуются в понятное сообщение для пользователя.

Неожиданные внутренние ошибки не раскрывают детали реализации и возвращают общее сообщение об ошибке.

---

# Защита от блокировок

При работе с внешним источником используются:

- timeout для HTTP-запросов;
- повторные попытки запросов;
- backoff между повторными попытками;
- выполнение парсинга в очереди вместо большого количества синхронных запросов из frontend.

Для production-сценария с большим количеством организаций дополнительно следует использовать:

- ограничение частоты запросов;
- ограничение количества одновременно выполняющихся задач;
- случайные задержки между запросами;
- exponential backoff;
- обработку HTTP 403/429;
- пул прокси при необходимости;
- ротацию User-Agent;
- circuit breaker при массовой недоступности источника.

Эти механизмы позволяют контролировать нагрузку на внешний источник и не выполнять большое количество запросов одновременно.

# Идемпотентность

Отзывы имеют внешний идентификатор Яндекс.Карт (`external_id`).

В базе данных установлен уникальный индекс:

```text
organization_id + external_id
```

Это не позволяет создать две одинаковые записи одного отзыва для одной организации.

При повторном полном парсинге текущая реализация формирует новый актуальный набор отзывов и заменяет предыдущий набор внутри транзакции.

Это обеспечивает отсутствие дублей и атомарное обновление данных: либо сохраняется новый полный результат, либо при ошибке старые отзывы остаются в базе.

---

# История изменений

В текущей версии хранится только актуальное состояние отзывов.

Для полноценной production-реализации истории изменений можно добавить сущность запуска парсинга, например:

```text
parsing_runs
----------------
id
organization_id
status
started_at
finished_at
error
```

и хранить связанные снимки отзывов:

```text
review_snapshots
----------------
id
parsing_run_id
external_review_id
rating
text
published_at
organization_reply
...
```

Тогда между двумя запусками можно определить:

- новые отзывы;
- изменённые отзывы;
- удалённые отзывы;
- изменения рейтинга;
- изменения ответа организации.

Был выбран более простой вариант, поскольку основная задача — получение актуального состояния карточки и отзывов.

# Структура базы данных

Основные сущности:

### organizations

Хранит подключённую организацию и её агрегированные данные:

- ссылка на Яндекс.Карты;
- название;
- средний рейтинг;
- количество оценок;
- количество отзывов;
- статус парсинга;
- ошибку парсинга;
- время начала и завершения парсинга.

### reviews

Хранит отзывы организации:

- внешний идентификатор;
- автор;
- рейтинг;
- текст;
- дата;
- ответ организации;
- дату ответа.

Связь:

```text
Organization 1 ──────── * Reviews
```

Отзывы удаляются вместе с организацией благодаря foreign key с каскадным удалением.

# API

Основные защищённые endpoints:

```text
GET    /api/user
GET    /api/organization
PUT    /api/organization
GET    /api/organization/reviews
```

API защищено Laravel Sanctum.

Отзывы возвращаются с pagination metadata Laravel, поэтому frontend может переключать страницы без повторного парсинга Яндекс.Карт.
